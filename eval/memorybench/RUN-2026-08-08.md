# MemoryBench comparison, 2026-08-08

First run of reMem inside a third-party harness alongside the systems it
competes with. Everything here is intended to be reproducible from this repo.

## What this run is

| | |
| --- | --- |
| Harness | [MemoryBench](https://github.com/supermemoryai/memorybench), MIT, **unmodified** |
| Benchmark | LoCoMo (MemoryBench's loader, 1,986 questions across 10 conversations) |
| Providers | reMem, mem0, Supermemory, `rag`, `filesystem` |
| Sample | 50 questions, 10 per category, stratified, seeded (42) |
| Answering model | `gpt-5-mini` |
| Judge | `gpt-4o` |
| reMem config | captured live in `config-remem-run1.json` |

The harness is Supermemory's own. It runs the same questions, pipeline, and
judge against every provider, and ships the `rag` and `filesystem` baselines
that multiple independent evaluations report memory systems failing to beat.
Winning there is a stronger claim than winning in our own harness.

## Decisions and why

### reMem runs with the consolidator OFF

`REMEM_CONSOLIDATOR=null`, so no beliefs are formed. This is a deliberate,
disclosed choice, not an accident.

- On LoCoMo the belief layer is worth **+2.3 points once, at top-50 only**
  (`docs/FINDINGS.md`, F4). LoCoMo is episodic recall, the axis reMem's own
  design notes never claimed for the belief layer.
- MemoryBench creates **one container per question**
  (`src/orchestrator/phases/ingest.ts:44`), so a conversation is re-ingested
  once per question. At LoCoMo's average of 588 turns per conversation, a
  125-question run means about 73,500 turns of LLM consolidation, roughly $27
  at the measured rate of $0.37 per 1,000 turns.
- Paying $27 for 2 points on the benchmark where beliefs matter least is a bad
  trade. The belief layer's real case is PrefEval, where it is worth **+20 to
  +27 points** (F3).

**Report this as reMem in retrieval-only mode.** It is not the full system.

### The sample is stratified and seeded

MemoryBench's `limit` sampling mode takes `slice(0, n)`, which for LoCoMo draws
every question from one conversation. Its `sample` mode stratifies but shuffles
with an unseeded `Math.random()`, and since each provider is a separate
orchestrator run, that would hand **every provider a different sample** and
silently invalidate the comparison.

`run-compare.ts` therefore stratifies once with a seeded PRNG and passes the
resulting `questionIds` explicitly to every provider. Verified: two independent
invocations produce an identical set. The log line `Using explicit questionIds:
50 questions` confirms the harness honoured it.

### Why n=50 rather than the full set

mem0 and Supermemory ingest on their own platforms and bill their own accounts.
We have no visibility into either. Fifty containers bounds that exposure while
still giving a stratified comparison. The intent is to measure actual
consumption from both dashboards after this run, then decide whether to scale.

**Consequence:** 10 questions per category means per-category differences will
be directional only, not significant. The overall number is the meaningful one.

### Answerer weaker than judge

A strong answerer reasons around gaps in retrieved context, which compresses the
differences between memory systems, and those differences are the measurement.
A strong judge reduces noise: LoCoMo's judge is documented as accepting 62.81%
of deliberately wrong answers. Splitting tiers (`gpt-5-mini` answering,
`gpt-4o` judging) also avoids a model grading its own output.

**Caveat:** a genuinely cross-vendor judge would be better, and was used in our
own harness earlier (`claude-sonnet-5`). MemoryBench calls provider APIs
directly with no base-URL override, so that would need an Anthropic key.

## Costs and who pays them

| Account | Expected | Visible to us |
| --- | --- | --- |
| OpenAI (answerer + judge + `rag` embeddings) | ~$1.50 | yes |
| OpenRouter (reMem consolidator) | **$0**, consolidator off | yes |
| mem0 | unknown, 50 containers x ~588 turns | no |
| Supermemory | unknown, same volume | no |

An earlier 125-question attempt was stopped after $6.11 of OpenRouter spend once
the consolidation cost became clear. That is what prompted turning the
consolidator off.

## Reproducing

```bash
git clone https://github.com/supermemoryai/memorybench
cd memorybench && bun install
bash ../eval/memorybench/apply.sh .
cp ../eval/memorybench/run-compare.ts .

# reMem adapter, retrieval-only, from the reMem repo root
REMEM_EMBEDDER=transformers REMEM_CONSOLIDATOR=null \
REMEM_RANK=observations-first REMEM_MIN_SCORE=0 REMEM_ALPHA=0.3 \
REMEM_WINDOW=1 REMEM_DEMOTE_SUPERSEDED=false PORT=8899 \
pnpm serve:mem0-adapter

# the comparison
bun run run-compare.ts \
  --providers remem,mem0,supermemory,rag,filesystem \
  --benchmark locomo --per-category 10 --seed 42 \
  --judge gpt-4o --model gpt-5-mini --run-id mb50
```

Requires `OPENAI_API_KEY` (a real OpenAI key, not a gateway), `MEM0_API_KEY`,
and `SUPERMEMORY_API_KEY` in `memorybench/.env`. Note that reMem's own
`.env.local` holds an OpenRouter key under the same variable name for its
consolidator; the two files must stay separate or each breaks the other.

## Limits to state alongside any number

1. reMem ran **without its belief layer**. Not the full system.
2. n=50, 10 per category. Category cells are too small for significance.
3. Single seed, single run. No variance estimate.
4. Judge and answerer are both OpenAI models, so not cross-vendor.
5. mem0 and Supermemory were run through MemoryBench's existing adapters,
   which we did not write and have not audited.
